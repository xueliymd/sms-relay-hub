# 设备二维码配置

## 使用流程

1. 在网页管理端的“设备”页创建一个 `Android 应用` 或 `Android Root` 设备；扫码端类型必须与设备类型一致。
2. 在该设备操作栏点击“生成扫码配置”。二维码有效期为 5 分钟，只能成功兑换一次。
3. Android 采集端点击“扫描后台二维码自动配置”，首次使用时允许相机权限；Root 模块打开本地控制台后点击“扫描二维码”，也可以选择二维码图片或粘贴二维码内容。
4. 扫码端通过二维码中的服务器地址和单次令牌调用 `/api/v1/enrollment/consume`。
5. 服务端兑换成功后返回当前设备的 HMAC 密钥；Android 采集端使用 Android Keystore 加密保存，Root 模块原子写入本地配置并立即启动转发服务。

## 安全设计

- 二维码只包含协议版本、服务器地址、设备 ID、短期随机令牌和过期时间，不包含长期 HMAC 密钥。
- 服务端只保存令牌 SHA-256 摘要，兑换成功后立即标记为已使用。
- 同一设备重新生成二维码会删除旧的待兑换令牌。
- 设备被撤销、恢复或轮换凭据时，已有待兑换令牌全部失效。
- 采集端校验二维码类型、版本、HTTP(S) 地址、设备 UUID 和过期时间，避免把其他二维码提交到配置接口。
- 生产环境应设置 `PUBLIC_BASE_URL=https://你的域名`；未设置时服务端按反向代理的 `X-Forwarded-Proto` 和 `X-Forwarded-Host` 生成地址。

## 当前限制

- 网页端负责生成二维码；Android 采集端和 Root 模块本地控制台分别提供扫码入口，原生轻量管理端不复制网页的设备修改功能。
- 二维码兑换后的 HMAC 密钥不会再次显示在扫码端界面，手工配置方式仍可继续使用。
- 本地已完成后端、网页、Root Go 测试和 Android Release 签名编译；真实手机摄像头扫描、Root 相机权限和公网 HTTPS 兑换仍需在部署服务器上做一次现场验收。
