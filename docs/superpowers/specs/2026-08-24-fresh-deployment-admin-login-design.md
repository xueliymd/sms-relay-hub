# 全新部署、端口配置与管理员登录设计

## 目标

发布一个不携带本地运行数据的服务器部署包，允许部署前自定义对外端口和容器内部应用端口，并把管理台日常认证从手工管理令牌改为单管理员用户名和密码登录。

## 全新部署边界

- 发布包只包含源码、静态资源、客户端文件、Docker 配置和 Alembic 表结构版本。
- 发布包禁止包含 `.env`、SQLite/PostgreSQL 数据、短信、设备、取码记录、运行缓存、虚拟环境和构建目录。
- Alembic 文件是空数据库的结构定义。首次启动对空 PostgreSQL 执行 `upgrade head`，只创建表，不导入本机数据。
- PostgreSQL 数据只存在服务器 Docker 命名卷 `postgres_data`。普通更新保留该卷；只有管理员显式执行带 `-v` 的销毁命令才清空数据。

## 端口模型

- `HTTP_PORT`：宿主机对外 HTTP 端口，默认 `80`。
- `HTTPS_PORT`：宿主机对外 HTTPS/TCP+UDP 端口，默认 `443`。
- `APP_PORT`：`app` 容器内部 Uvicorn 端口，默认 `8000`；Caddy 使用同一变量转发，不映射到公网。
- 本机调试脚本提供 `-BackendPort` 和 `-WebPort`；`5173` 只用于 Vite 开发预览，生产容器不启动 Vite。
- 端口在进程启动前由 `.env` 和 Docker Compose 绑定，管理网页不直接修改端口。修改 `.env` 后通过 Compose 重建/重启生效。

## 管理员认证

- 系统只有一个管理员账号。
- `ADMIN_USERNAME` 和 `ADMIN_PASSWORD` 只用于首次空库创建管理员；数据库已有管理员后不覆盖其修改。
- 密码使用 Argon2 哈希存储，数据库不保存明文密码。
- `POST /api/v1/admin/login` 校验用户名密码，返回由 `ADMIN_TOKEN` HMAC 签发的短期管理会话。
- 会话包含管理员名、过期时间和 `session_version`；修改用户名或密码后递增版本，旧会话立即失效。
- 管理 API 继续使用 `X-Admin-Token`，既接受短期管理会话，也接受 `ADMIN_TOKEN` 故障恢复令牌，兼容现有自动化和维护命令。
- 管理台提供修改用户名和密码的设置，要求输入当前密码；修改成功后返回新会话。
- 浏览器只把短期会话保存在 `sessionStorage`，关闭标签页后不长期保留。

## 初始化输出

- 初始化脚本仅在值缺失时生成 `ADMIN_PASSWORD`、`ADMIN_TOKEN`、`DATA_ENCRYPTION_KEY` 和 PostgreSQL 密码。
- 首次生成时在终端打印管理地址格式、管理员用户名、管理员密码和恢复令牌，并提示妥善保存。
- 重复执行不会覆盖已有非空值，也不会重复打印已有密码。

## 验证

- 后端测试覆盖首次建管理员、正确/错误登录、过期/篡改会话、修改密码后旧会话失效、恢复令牌兼容。
- 前端测试覆盖用户名密码登录、会话恢复、退出和修改登录信息。
- 部署测试覆盖三类端口变量、Caddy 转发、初始化输出和发布包禁止项。
- 最终 ZIP 再次扫描禁止项，并运行后端、前端、Air724 契约、静态检查和生产构建。
