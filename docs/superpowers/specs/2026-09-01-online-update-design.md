# Online Update Design

## Goal

Provide safe self-hosted Android update notifications and installation while preserving compatibility with the currently distributed APK. Keep release history on the platform and prevent corrupt, mismatched, downgraded, or differently signed APKs from reaching the system installer.

## Signing Compatibility

The distributed Android 1.0.8 APK is signed by the local Android Debug certificate with SHA-256 fingerprint `f6bfe7a63a07950244cc0a8e21f551bdce9cd5bd375c22876de2d97eaaab27ff`. The matching private key still exists and its certificate is valid until 2056-07-13.

To avoid forcing existing devices to uninstall, migrate that private key into a dedicated access-controlled PKCS12 release keystore without changing the certificate. All future release APKs must use this certificate. Debug builds remain separate.

## Release Catalog

The platform serves a public, read-only JSON catalog:

- `GET /api/v1/releases/android/latest?channel=stable&current_version_code=9`
- `GET /api/v1/releases/android/history?channel=stable`

Each release contains platform, channel, version code/name, published time, minimum SDK, mandatory flag, notes, size, SHA-256, signer certificate SHA-256, and a same-origin download URL.

The catalog is generated by a release publishing script. Publishing copies the APK into a versioned directory, verifies its package/version/signature, calculates SHA-256, atomically updates the catalog, and retains the newest five versions by default.

## Android Flow

1. Check on app launch, manual button, and periodic WorkManager execution.
2. If a newer version exists, save the release metadata and show a notification.
3. Download only from the configured platform origin into app-private cache.
4. Verify file size and SHA-256.
5. Verify package name, strictly increasing version code, manifest version match, and signing certificate compatibility with the installed app.
6. If unknown-source permission is missing, open the per-app system setting.
7. Use FileProvider and the Android package installer. Never click through or silently install.
8. Keep the downloaded verified APK until installation is launched or a newer release replaces it.

## Failure Handling

- Network errors keep the current version running and retry later.
- Hash, package, version, or signer mismatch permanently rejects that download and records a safe status.
- An install cancellation does not modify the current app.
- Ordinary Android downgrade is not used. A rollback is published as old code rebuilt with a newer version code and the same signing certificate.
- Database and config changes must remain backward compatible before a rollback release is offered.

## Push Semantics

The self-hosted default uses a tiny 15-minute WorkManager catalog check plus checks on launch and manual request. This does not depend on Google services and works on devices without FCM. FCM can be added later as an optional immediate wake-up channel; it is not required for correctness.

## Root And Container Scope

The catalog schema supports Root and container artifacts, but this implementation first completes Android APK updates. Root installation must be confirmed in Magisk/KernelSU/APatch. Container updates must run through a server-side script that backs up the database and environment before switching a pinned version; neither path may silently self-modify from the Android app.
