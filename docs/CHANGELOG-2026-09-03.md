# 修复记录

## 2026-09-05 Android 管理端

- 短信页改为固定状态卡和设备/SIM 筛选卡，短信记录使用独立滚动列表，不再把状态、筛选和全部记录挤在同一个长页面里。
- 实时刷新只更新列表数据，不再重建整页，避免新短信到达后滚动位置跳回顶部。
- 接近列表底部时自动加载更早短信，也保留“加载更早短信”按钮。
- “补拉遗漏短信”文案改为“正在同步最近短信”，明确这是断线恢复动作，不代表软件端使用了另一个数据库。
- 管理端仍通过同一个管理员 API 读取平台数据：登录后先取最近 500 条，继续下拉时按当前设备/SIM 筛选分页读取，WebSocket 只负责实时增量。

## 2026-09-05 采集端与 Root 模块

- 采集端 1.0.14：本地加密队列超过 500 条时仅清理已上传、冲突和永久失败记录，不再误删待上传短信。
- Root 模块 0.3.10：上传失败立即退避并停止本轮逐条硬试；WS/MQTT 超时降为 10 秒，HTTP 回退为 5 秒连接、15 秒总等待；Web 控制台改为吸顶导航、状态卡、分区卡片和底部固定保存。

## 2026-09-03

- 可从应用内直接打开应用信息或无障碍设置；无障碍服务仍然是可选保活，不读取页面内容、不执行点击。

- 登录后默认进入“短信”页，不再自动选择第一台设备。
- 默认订阅全部设备的实时短信；选择设备和 SIM 仅作为可选筛选条件。
- 短信卡片显示设备名称、发送方、SIM、完整正文和时间信息。
- 增加“加载更早短信”，按当前设备/SIM筛选继续读取历史记录。
- 导航顺序调整为“短信、平台、设备/SIM、接口”。

## 服务端实时协议

- 管理员 WebSocket 的 `subscribe` 帧允许省略 `device_id`，省略时接收全部设备的已提交短信。
- 保留填写 `device_id` 时的单设备订阅和 `sim_slot` 筛选兼容性。
