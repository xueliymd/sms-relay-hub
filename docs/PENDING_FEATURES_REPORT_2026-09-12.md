### 2. HMS 厂商推送唤醒（FCM 可选）

- 当前：`backend/app/services/push.py` **不存在**，`devices` 表无 `push_token` / `push_channel` 字段
- 完整实施方案已写入 `DEFERRED_FEATURES.md` 3.4 节（平台 0.5 天 + 设备端 1 天 + 真机联调 1 天）

### 3. 远程控制 v2（敏感指令集，对齐交接文档原清单）

交接文档原始需求为 5 类：**发短信、查短信、查通话、查话簿、查电量**。

v1 已实现：查电量（`query_battery`）、查最近短信（`query_recent_sms`）、触发立即上报（`trigger_upload`，本轮新增）。
**v1 未实现**：
- `send_sms`（发短信，需 SEND_SMS 权限）
- 查通话记录（需 READ_CALL_LOG）
- 查话簿 / 联系人（需 READ_CONTACTS）

要求：设备端逐项授权开关 + 二次确认 + 完整审计（v1 的授权框架已具备，可直接复用）。工作量约 4~6 天。

## 五、状态更新（2026-09-12 晚，平台侧修复轮）

本节的结论**优先于**上文对应条目。

### 已完成
1. **后端 REST 短信补 `otp_code`**：`_serialize_message` 此前不输出该字段，只有 WebSocket 路径补，
   导致两类真实故障——① 管理端 App 的"验证码"按钮（`MessageScreen.kt` 已解析 `otp_code`）永远不出现；
   ② 网页"设备实时短信"面板在断线重连时用 REST 补拉结果**按 id 覆盖** WS 收到的同一条消息
   （`LiveMessagePanel.mergeMessages`），验证码按钮会**凭空消失**。现 `_serialize_message` 统一带出，
   规则与 WS 完全一致（仅 `available` 且未过期才回码，已领取/已过期只留 `otp_status`）。
   列表接口用**批量查询**（`store.get_otp_states`，同时返回 status 与 code）避免 N+1；单条已读/未读接口同样带上。
   新增测试锁死"REST 与 WS 同一条消息字段完全一致"。
2. **`/admin/runtime` 补 `latest_releases`**（各平台 stable 最新版本，直接读发布清单，清单不可读时降级为空对象不 500）；
   网页运行信息面板新增"最新发布版本"一行。`certificate_expires_at` 恒为 `null` 并已在设计侧说明原因
   （TLS 由上游反代终结，容器内不持有证书）——保留字段是为了让客户端区分"不适用"与"漏返回"。
3. **新 APK 进发布清单**：采集端 **1.0.22 (code 23)**、管理端 **1.0.10 (code 11)** 已复制到
   `web/public/assets/releases/{android/23,manager/11}/`，`release-catalog.json` 已更新，
   `assets/downloads/Relay-SMS-Forwarder.apk` 直链同步为 1.0.22。**1.0.21 / 1.0.9 未单独发布**
   （已被 1.0.22 / 1.0.10 取代，且 1.0.21 含磁贴回归 bug，不宜进历史列表）。
4. **文档纠错**：`DEPLOYMENT_AUDIT_2026-08-23.md` 的"容器内部固定监听 8000"改为 `APP_PORT`（默认 39200）、
   443/QUIC 映射已移除、并补充回滚语义/健康检查 `start_period` 的更正；
   本文的版本号与磁贴状态按实际修正。
