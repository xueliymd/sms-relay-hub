# 最终全方面功能审查

## 2026-09-02 续审

- 已补入可选 Air724 MQTT 短信上报适配：Air724 独立 MQTT 上传脚本、服务端 HMAC/幂等接收接口和 Docker Compose `mqtt` profile；默认部署不启动 MQTT bridge，不影响原有 HTTP/WebSocket 链路。
- MQTT bridge 使用持久会话、手动 ACK 和按实例隔离的 `MQTT_CLIENT_ID`；瞬时转发失败不确认消息，避免多实例互相顶线或丢失待转发短信。
- 已将快捷指令设备生成的 ISO UTC 时间纳入请求，服务端校验无效值并回退服务器接收时间；原有一次性临时错误重试保留。
- 已修复管理端在服务器未配置 `PUBLIC_BASE_URL` 时登录后加载失败的问题，空公开地址现在回退显示当前连接地址；管理端 API 页面增加 MQTT 上报接口。

- 已修复网页消息页默认自动选中第一台设备的问题：进入消息页后默认保持“请选择设备”，只有管理员主动选择后才加载对应设备的实时短信。

## 结论

当前交付链路已经闭环：手机采集端负责收短信和上报，网页端负责完整后台管理，原生管理端负责登录后查看选定设备的实时信息，Root 模块和容器均有版本清单及历史归档。

没有发现本轮新增功能中的 P0 阻断问题。需要明确的是：原生管理端按此前确认的范围保持“轻量只读”，网页端才提供设备、消息、SIM 映射和账号等修改操作；这不是两个端功能不一致，而是职责划分。

## 原生管理端审查

### 已有

- 多平台地址配置和切换，支持 HTTP/HTTPS；HTTP 登录会明确提示明文风险。
- 登录、退出、session 失效处理、指数退避重连和 60 秒 WebSocket 心跳。
- 选定设备和 SIM 过滤；短信正文、发送方、接收号码脱敏、SIM、subscriptionId、OTP 和时间展示。
- WebSocket 先认证、再订阅；REST cursor 补拉，避免断线丢短信；服务端 401/403 能回到登录页。
- 运行信息、端口、数据库安全摘要、服务状态、四类发布历史和下载入口。
- 多平台账号本地加密保存；密码“保留/清除”语义已覆盖，删除平台时同步删除密码和 session。

### 有意未做

- 原生 App 没有设备创建、设备凭据轮换、撤销/恢复/永久删除。
- 原生 App 没有消息标记已读、删除、批量删除和保留清理。
- 原生 App 没有修改 SIM 手机号映射、修改管理员账号、创建/撤销脚本 API 令牌。
- 原生 App 没有后台常驻监控任务；只有用户打开后刷新，符合“不需要后台 15 分钟检查”的决定。

这些操作网页端已经提供；如果后续要让手机管理端也能修改，再单独增加带二次确认和权限分级的写操作，不建议把当前只读端直接改成全权限。

## 参考项目对照

参考项目在采集端体验上更丰富，主要包括多转发渠道、关键词/白名单/黑名单过滤、模板、定时转发、配置导入导出、失败日志、网络状态、通道测试、电量/充电提醒和更完整的厂商设置向导。

当前项目没有照搬这些与中央平台职责冲突的功能：

- 没有多第三方通知渠道；当前统一上报到自托管平台，再由平台管理。
- 没有本地关键词过滤；避免手机端过滤导致平台无法审计原始短信。
- 没有本地配置导入导出和历史短信页；敏感配置通过平台设备凭据和加密队列管理。
- 没有 RCS/5G 消息保证；这受系统广播和 ROM 限制，保活不能解决。

已吸收的兼容性经验包括：前台服务、网络恢复、失败队列、可选 SIM 元数据、双卡多来源解析、保活设置入口和可见状态。当前方案额外增加了 HMAC、防重放、服务端幂等、实时管理员流和统一版本校验。

## 在线更新与部署审查

- Android APK 发布前检查包名、版本、大小、SHA-256 和签名证书摘要；安装前再次校验并交给系统安装器确认。
- Root 和容器更新包均有 SHA-256；Root 仍需 Root 管理器或用户确认，不静默刷入。
- 容器更新包不嵌入自身 release store，避免发布包把自己的哈希再次包含进去造成自引用。
- 完整部署包包含清单和所有已发布制品，不包含 .env、签名文件、数据库、debug APK 或本地缓存。
- 发布脚本已经修复 Windows PowerShell 的 UTF-8 JSON 读取/写入兼容性。
- 当前设计不做后台定时检查，只做应用启动检查和用户手动检查；快捷指令也不引入后台轮询。
- 快捷指令仍保持最小 `{message}` 请求；设备 `Date` 显示为 `message_date`，服务器 `received_at` 单独保留，网络/5xx 只允许复用原请求重试一次。
- MQTT 不接入 iPhone 快捷指令；Air724 的 MQTT 短信上传已作为独立适配器，不改变现有 WebSocket 取码、Android HTTP/HMAC 和 iPhone Bearer 合同。同一 Air724 设备不要同时混用取码脚本和 MQTT 上传脚本。

## 审查结论
