## 五、iOS 快捷指令 received_at 字段问题（已验证修复，2026-09-09 关闭）

### 结论（2026-09-09 复审）

**当前后端代码已完全宽容化，该问题在服务端已解决，无需再改代码。**
验证方式：新增回归测试 `backend/tests/test_received_at_hostile.py`
（数组/对象/嵌套对象/epoch 秒/epoch 毫秒/bool/乱字符串/斜杠格式/中文格式/
无时区/空串/null 共 12 种敌意 `received_at` → 全部 201 入库或 200 幂等去重，
无一 422）。全量 relay 套件 106 项通过。部署包（catalog-bom-fix）内 relay.py
与工作区逐行一致。

### 解析规则（`_parse_shortcut_received_at`，backend/app/api/relay.py:1043）

- ISO 8601 字符串（含时区）→ 使用手机时间
- epoch 秒/毫秒数字 → 使用手机时间
- **其余一切**（无时区、中文/斜杠格式、数组、对象、乱串、空值）→
  静默回退服务器时钟，照常入库

### 用户侧快捷指令正确配置（推荐加回精确时间）

「格式化日期」→ 日期格式选**自定义** → 格式串：

```
yyyy-MM-dd'T'HH:mm:ssZZZZZ
```

- `T` 两边有单引号，结尾是**五个 Z**
- 预览应显示 `2026-09-07T22:15:30+08:00`（后端可解析，使用手机真实时间）
- 配错也不会再 422——最坏情况回退服务器时间（差约 1 分钟）

### 2026-09-09 补充：同短信双时间重复入库（已修复）

用户配置 received_at 后出现「同一条短信入库两条，一条设备时间、一条服务器时间」。
根因：**幂等分钟桶（fallback_date）取自 received_at**——iOS 重发同一短信时
received_at 变化（重试跨分钟/时钟微差/一次带字段一次不带），生成不同的
client_message_id，幂等失效 → 重复入库。

修复（backend/app/api/relay.py `build_shortcut_payload`）：分钟桶改锚
**服务器时钟**（`datetime.now()` 的分钟），received_at 只用于落库精确接收时间，
不参与幂等键。测试更新：跨分钟重发同文 → 200 幂等去重（新增端到端回归
`test_same_sms_resend_with_different_received_at_is_deduplicated`），
全套 228 项通过。已打入部署包
`sms-relay-hub-update-2026.09.09-shortcut-dedup-fix.zip`
（sha256 前 16 位 9a51f1e232ca8855，含采集端 1.0.15 APK 与 catalog）。

### 2026-09-09 最终方案：设备时间为主，服务器时间仅兜底

按用户确认的最终形态落地（三端联动）：

1. **后端**（relay.py）：展示时间优先级 = 消息 Date 字段 > `received_at`
   （iOS 设备时间，source=`device_received_at`）> 服务器分钟（仅未传时兜底）。
2. **幂等**：分钟桶只锚**服务器时钟**；幂等请求哈希排除
   `message_date`/`message_date_source`（展示时间变化不产生 409/重复）。
3. **管理端 1.0.6**（versionCode 7）：短信列表只显示一个时间（设备时间优先），
   移除并排的“平台入库时间”。
4. **脚本 API 无影响**：WS/Claim 读消息表单条记录，OTP 事件只含
   `received_at` 单一时间；重发由幂等去重（端到端实测：201 → 200 → 200，
   只入库一条）。
5. **教程**：DEVICE_TUTORIAL.md C 节 + Web 演示教程页第 2 节，含
   `yyyy-MM-dd'T'HH:mm:ssZZZZZ` 自定义格式串配置步骤。
