# iPhone 快捷指令：稳定转发配置

这套配置把短信字段、去重 ID 和验证码解析交给服务端处理。iPhone 负责把自动化收到的整条信息和“当前日期”通过 Bearer Token 发到简化入口；失败时最多按同一请求重试一次。

## 一、自动化

在“快捷指令”App 中创建：

```text
自动化 -> 信息 -> 信息包含：验证码 -> 立即运行
```

执行动作配置为：

```text
运行快捷指令：文本
输入：输入快捷指令的信息
```

这里的“输入快捷指令的信息”必须是整条信息，不要改成“内容”。这样服务端有机会读取发件人、正文和消息日期；部分 iOS 版本还会附带接收手机号，服务端会自动使用它做双卡路由。消息对象自带的 `Date` 会作为 `message_date` 保存；另外用“当前日期”动作生成 `received_at`，不要手工拼接时间戳。

如果当前 iOS 版本不提供接收手机号或 Subscription，短信仍会先入库。只有当该设备后台绑定了多个手机号时，才需要在后台把正确的 SIM/手机号映射到对应设备，否则脚本按手机号订阅时会显示超时，因为平台无法判断该短信属于哪条线。

### 触发条件的选择

- 只转发验证码时，保留“信息包含：验证码”。
- 如果短信供应商使用“校验码”或“动态码”，分别增加对应关键词自动化；一个关键词不会覆盖其他文本。
- 如果 iOS 版本提供“收到信息”而不要求关键词，想转发全部短信时再使用它。
- 不采用第三方项目里的“单个空格”通用触发技巧：它可能让自动化出现“立即运行”，但对没有空格的中文短信并不可靠。

首次排查“第一条短信没转发”时，先看快捷指令的运行记录：没有运行记录是触发条件问题；有运行记录但平台没有 `201`/`200 duplicate` 是网络或请求动作问题；平台已返回成功但管理台延迟，则检查管理台实时连接或重新拉取消息。

## 二、原来的“文本”快捷指令只保留三个动作

### 动作 1：Token 文本

保留一个“文本”动作，只填写后台创建 iPhone 设备时显示的一次性设备 Token。

不要填写 `Bearer ` 前缀；前缀在请求头里单独配置。

### 动作 2：当前日期

添加“当前日期”动作，再添加“格式化日期”动作，格式选择 `ISO 8601`，时区选择 `UTC`。把结果命名为 `ReceivedAt`。如果你的 iOS 版本的“当前日期”已经输出 ISO 8601 文本，可以直接使用，不要再二次拼接。

### 动作 3：获取 URL 内容

把 URL 改成：

```text
<RELAY_BASE_URL>/api/v1/ingest/shortcut
```

其中 `<RELAY_BASE_URL>` 是服务器 HTTP/HTTPS 根地址，例如：

```text
http://192.168.5.7:39300
```

方法选择：

```text
POST
```

请求头只保留两项：

```text
Authorization    Bearer + 上面的 Token 文本变量
Content-Type     application/json
```

请求体选择 `JSON`，只建立一个字段：

```text
键           message
值           输入快捷指令的信息
键           received_at
值           ReceivedAt
```

值必须从“选择变量”中选择：

```text
输入快捷指令的信息
```

不要选择黄色图标的 Token“文本”变量。

## 三、不要再添加的内容

以下内容全部由服务端自动生成，手机端不要再创建：

```text
schema_version
client_message_id
sender
body
source
metadata
X-Idempotency-Key
SHA-256
格式化消息日期
创建名为“快捷指令名称”的快捷指令
```

服务端会从整条信息中自动读取：

```text
sender       <- Sender / 发件人
body         <- Content / 内容
message_date <- Date / 日期
```

`received_at` 只使用 iPhone 的“当前日期”结果；如果日期格式无效，服务端回退到服务器接收时间，不会因为时间字段导致短信丢失。

如果 iOS 只传出了普通文本，服务端仍会接收正文，发件人会标为 `iPhone Messages`。

## 四、响应

```text
201                 首次同步成功
200 duplicate=true  同一短信重复触发，未重复保存
401                 Token 无效、轮换或设备已撤销
413                 请求太大
422                 没有传入 message 或正文为空
```

快捷指令不需要显示完整响应正文，避免把短信正文或验证码显示在日志中。

## 五、失败重试

只对临时故障重试一次，重试必须复用第一次的完整 URL、请求头和 JSON，不要重新生成正文、日期或任何幂等字段：

```text
网络失败、408、425、429、500-599
    -> 等待 2 秒 -> 使用同一个“获取 URL 内容”请求再试一次
401、409、413、422 或 200/201
    -> 不重试，直接结束
```

如果当前 iOS 支持“尝试/否则（Try/Otherwise）”，把第一次“获取 URL 内容”放在“尝试”中，把“等待 2 秒 + 同一请求”放在“否则”中。若系统只提供“出错时继续”，也必须用一次性条件控制，不能无条件发送第二次请求。服务端幂等键由整条短信内容、设备时间和设备凭据推导，重复请求最多返回 `200 duplicate=true`，不会重复入库。

调试阶段可以在最后添加通知动作，只显示“已同步 / 重复同步 / 网络失败 / Token 无效”，不要显示完整短信正文或 Token；确认稳定后删除通知动作。

## 六、安全

- Token 只放在 `Authorization` 请求头。
- 不要把 Token 写进 JSON、URL、截图或分享的快捷指令。
- 你之前截图里已经暴露过 Token，正式使用前应在后台轮换一次。
- 分享快捷指令前，先删除本机真实 Token；接收者必须使用自己的设备 Token。
